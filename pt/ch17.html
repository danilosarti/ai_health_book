Como usar este capítulo

Começando por aqui?

Este capítulo se apoia diretamente nos dois capítulos anteriores e nas redes neurais do Capítulo 7. Em poucas linhas:

  • O texto é dividido em tokens (palavras ou pedaços de palavras) retirados de um vocabulário \(\mathcal{V}\); o token na posição \(t\) é escrito \(w_t\) (Capítulo 15).
  • Um modelo de linguagem atribui uma probabilidade a uma sequência de tokens. Pela regra da cadeia da probabilidade, \(P(w_1, \dots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_{<t})\), de modo que toda a tarefa se reduz a prever o próximo token a partir dos anteriores. Um modelo de n-gramas olha apenas para os últimos \(n-1\) tokens; uma rede recorrente (RNN) comprime todo o passado em um único vetor oculto (Capítulo 16).
  • Cada token é representado por um embedding, um vetor aprendido \(\mathbf{e}_w\) de números no qual palavras semelhantes acabam ficando próximas (Capítulo 16).
  • A softmax transforma um vetor de escores \(z_1, \dots, z_C\) em probabilidades positivas que somam 1, \(e^{z_c} / \sum_{c'} e^{z_{c'}}\) (Capítulo 7); um modelo de linguagem a usa para atribuir uma probabilidade a cada próximo token possível, e é treinado minimizando a entropia cruzada, a média de \(-\log P(\text{próximo token observado})\) (Capítulo 16).
  • Uma rede neural é construída com camadas de somas ponderadas seguidas de uma função de ativação não linear; seus pesos são aprendidos por descida do gradiente, com gradientes calculados por retropropagação (Capítulo 7). Um modelo é uma representação simplificada construída com um propósito (Definição 1.3) e fornece informação a uma decisão (Definição 1.4).

Uma revisão de dois minutos sobre vetores e matrizes
  • Um vetor é uma lista de números, como \(\mathbf{a} = (2, 0)\). O produto escalar de dois vetores de mesmo comprimento multiplica-os entrada por entrada e soma: \((2, 0) \cdot (1, 3) = 2 \times 1 + 0 \times 3 = 2\). Ele é grande e positivo quando os dois vetores apontam na mesma direção, próximo de zero quando não têm relação e negativo quando apontam em direções opostas.
  • Uma matriz é uma tabela de números; \(\mathbf{X}\) com \(T\) linhas e \(d\) colunas é “\(T \times d\)”. Aqui cada linha é um token.
  • O produto de matrizes \(\mathbf{A}\mathbf{B}\) é uma tabela de produtos escalares: a entrada \((t, s)\) é o produto escalar da linha \(t\) de \(\mathbf{A}\) pela coluna \(s\) de \(\mathbf{B}\). Ele exige que o número de colunas de \(\mathbf{A}\) seja igual ao número de linhas de \(\mathbf{B}\): uma matriz \(T \times d\) vezes uma matriz \(d \times d_k\) dá uma matriz \(T \times d_k\).
  • A transposta \(\mathbf{B}^{\top}\) troca linhas por colunas. Assim, \(\mathbf{Q}\mathbf{K}^{\top}\) é a tabela de produtos escalares entre cada linha de \(\mathbf{Q}\) e cada linha de \(\mathbf{K}\).
  • Em R, o produto de matrizes é A %*% B e a transposta t(B); em Python (numpy), são A @ B e B.T.

17.1 Por que olhar para trás é difícil

Todo modelo de linguagem, do mais simples ao maior, estima a mesma coisa: a probabilidade do próximo token dados os anteriores, \[ P(w_t \mid w_{<t}) = P(w_t \mid w_1, w_2, \dots, w_{t-1}) . \qquad(17.1)\] A regra da cadeia que leva à Equação 17.1 é uma identidade: ela não supõe que as palavras sejam independentes, apenas escreve a probabilidade de uma frase inteira como um produto de previsões do próximo token (Capítulo 16). O que difere entre os modelos não é esse objetivo, mas a forma como representam o contexto \(w_{<t}\): quanto dele conseguem ver e como decidem quais partes importam.

Na nota de Seán, as palavras decisivas, vancomicina e contraste, estão longe da palavra que está sendo interpretada. A linguagem clínica real está cheia dessas dependências de longo alcance: um pronome se refere a um paciente mencionado frases antes; uma negação como “nega” muda o sentido de um sintoma várias palavras depois; uma instrução no início de uma carta vale para tudo o que vem abaixo. Os modelos anteriores lidam mal com elas, de duas maneiras (Jurafsky e Martin 2026).

  • Uma janela fixa. Um modelo de n-gramas guarda apenas os últimos \(n-1\) tokens, \(P(w_t \mid w_{<t}) \approx P(w_t \mid w_{t-n+1}, \dots, w_{t-1})\). Tudo o que vem antes é invisível. Alargar a janela não resolve: o número de contextos possíveis cresce exponencialmente com \(n\), de modo que a maioria dos contextos longos nunca aparece no treino.
  • Um gargalo. Uma rede recorrente lê um token de cada vez e leva adiante um único vetor oculto, \(\mathbf{h}_t = g(\mathbf{h}_{t-1}, \mathbf{e}_{w_{t-1}})\). Em princípio, ela pode lembrar de qualquer coisa; na prática, todo o passado precisa caber em um vetor de comprimento fixo, e a informação de muito tempo atrás se apaga (Hochreiter e Schmidhuber 1997; Y. Bengio, Simard, e Frasconi 1994).

17.2 Atenção: uma consulta suave e aprendida

Pense em como Seán usa a prescrição. Ele tem uma pergunta em mente (“há algo nesta prescrição que seja tóxico para os rins?”). Cada linha da prescrição tem um rótulo (o nome do medicamento) e um conteúdo (dose, via, data de início). Ele compara a pergunta com cada rótulo e lê o conteúdo das linhas que correspondem. Um banco de dados faz o mesmo com correspondências exatas: uma consulta, uma chave correspondente, um valor devolvido.

A atenção é uma versão suave dessa consulta. Em vez de devolver o conteúdo da única melhor correspondência, ela devolve uma média ponderada de todos os conteúdos, com pesos que crescem com o quanto cada rótulo corresponde à pergunta. Os pesos são positivos e somam 1, então se comportam como probabilidades: uma parcela de atenção dada a cada token anterior.

Definição 17.1 (Atenção) A atenção é uma operação que constrói uma nova representação para uma posição \(t\) como uma média ponderada das representações das posições para as quais ela pode olhar, \[ \mathbf{c}_t = \sum_{s} \alpha_{ts}\, \mathbf{v}_s, \qquad \alpha_{ts} \ge 0, \quad \sum_{s} \alpha_{ts} = 1 , \qquad(17.2)\] em que \(\mathbf{v}_s\) é o conteúdo (valor) oferecido pela posição \(s\) e o peso de atenção \(\alpha_{ts}\) mede o quanto a posição \(s\) é relevante para a posição \(t\). Os pesos são calculados a partir dos próprios dados, separadamente para cada posição e cada entrada. Quando as posições pertencem à mesma sequência, a operação é chamada de autoatenção (self-attention).

Duas características tornam a atenção diferente de tudo o que vimos no Capítulo 16. Primeiro, nada é descartado: cada token anterior continua diretamente acessível, por mais distante que esteja. Segundo, os pesos não são fixados pela posição (“as duas últimas palavras”), mas calculados a partir do conteúdo: a mesma posição pode ser ignorada em uma frase e ser decisiva na seguinte.

A ideia surgiu na tradução automática. Bahdanau, Cho, e Bengio (2015) permitiram que um modelo recorrente de tradução, a cada palavra de saída, olhasse para todas as palavras da frase de origem e as ponderasse; o modelo aprendeu sozinho a alinhar cada palavra francesa com as palavras inglesas que ela traduzia. Vaswani et al. (2017) perguntaram então se a recorrência era mesmo necessária e construíram um modelo em que a atenção faz todo o trabalho de mover informação entre as posições. Eles o chamaram de transformer. O restante deste capítulo o desmonta peça por peça.

Para a palavra “urina” da nota de Seán, um modelo dá o mesmo peso de atenção a cada um dos 30 tokens anteriores. O que é \(\mathbf{c}_t\), a saída da atenção para “urina”?

17.3 Consultas, chaves e valores

De onde vêm os pesos? Cada token desempenha três papéis ao mesmo tempo, e o transformer lhe dá três vetores diferentes, um para cada papel.

Definição 17.2 (Consulta, chave e valor) Cada vetor de token \(\mathbf{x}_t\) que entra em uma camada de atenção é multiplicado por três matrizes aprendidas, o que dá \[ \mathbf{q}_t = \mathbf{x}_t \mathbf{W}_Q, \qquad \mathbf{k}_t = \mathbf{x}_t \mathbf{W}_K, \qquad \mathbf{v}_t = \mathbf{x}_t \mathbf{W}_V . \] A consulta (query) \(\mathbf{q}_t\) descreve o que a posição \(t\) está procurando; a chave (key) \(\mathbf{k}_s\) descreve o que a posição \(s\) oferece para ser encontrada; o valor (value) \(\mathbf{v}_s\) é o conteúdo que a posição \(s\) repassa quando recebe atenção. Empilhando as linhas, obtêm-se as matrizes \(\mathbf{Q} = \mathbf{X}\mathbf{W}_Q\), \(\mathbf{K} = \mathbf{X}\mathbf{W}_K\) e \(\mathbf{V} = \mathbf{X}\mathbf{W}_V\).

As matrizes \(\mathbf{W}_Q\), \(\mathbf{W}_K\) e \(\mathbf{W}_V\) são pesos comuns de uma rede neural, aprendidos por descida do gradiente como os do Capítulo 7. Ninguém diz ao modelo que “dor” deve procurar negações ou que “nega” deve se anunciar como uma: o modelo descobre quaisquer consultas e chaves que melhorem suas previsões. A atenção, portanto, não é uma regra aplicada ao texto de fora; é um cálculo neural aprendido.

A correspondência entre uma consulta e uma chave é medida pelo produto escalar, que é grande quando os dois vetores apontam na mesma direção. Dividir por \(\sqrt{d_k}\) e aplicar uma softmax a cada linha transforma as correspondências em pesos, e os pesos fazem a média dos valores. Em forma matricial, esta é a fórmula no coração de todo transformer (Vaswani et al. 2017): \[ \operatorname{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \operatorname{softmax}\!\left( \frac{\mathbf{Q}\mathbf{K}^{\top}}{\sqrt{d_k}} \right) \mathbf{V} , \qquad(17.3)\] em que a softmax é aplicada a cada linha separadamente. A linha \(t\) do resultado é o \(\mathbf{c}_t\) da Equação 17.2, e a linha \(t\) da softmax contém os pesos \(\alpha_{t1}, \dots, \alpha_{tT}\). A Figura 17.2 acompanha o cálculo passo a passo.

17.3.1 Por que dividir por \(\sqrt{d_k}\)?

O escalonamento não é enfeite. Um produto escalar soma \(d_k\) produtos, então, à medida que os vetores ficam mais longos, os escores se espalham. Se as entradas das consultas e das chaves são aproximadamente independentes, com média 0 e variância 1, o produto escalar tem variância \(d_k\), e seu tamanho típico cresce como \(\sqrt{d_k}\) (Vaswani et al. 2017). Escores grandes empurram a softmax para os extremos: um token fica com quase todo o peso, os outros com quase nada, e os gradientes dos quais o treino depende ficam minúsculos. Dividir por \(\sqrt{d_k}\) traz os escores de volta a uma dispersão de cerca de 1, qualquer que seja a dimensão. A simulação abaixo sorteia consultas e chaves aleatórias e mostra isso (Tabela 17.1).

17.4 Máscaras: quem pode olhar para quem

Até agora, cada token podia prestar atenção a todos os outros, inclusive aos que vêm depois dele. Para um modelo que lê uma nota inteira e a classifica, é exatamente isso que queremos. Para um modelo que gera texto um token de cada vez, é trapaça. A regra da cadeia na Equação 17.1 pede a probabilidade de \(w_t\) dados os tokens anteriores. Se, durante o treino, a posição \(t\) pudesse olhar para a posição \(t+1\), o modelo simplesmente copiaria a resposta que deveria prever e não aprenderia nada que pudesse usar quando o futuro fosse realmente desconhecido.

A correção não altera o cálculo da atenção; ela altera os escores antes da softmax.

Definição 17.3 (Máscara causal) Uma máscara causal impede cada posição de prestar atenção às posições seguintes. Uma matriz de máscara \(\mathbf{M}\) com \(M_{ts} = 0\) se \(s \le t\) e \(M_{ts} = -\infty\) se \(s > t\) é somada aos escores, \[ \operatorname{softmax}\!\left( \frac{\mathbf{Q}\mathbf{K}^{\top}}{\sqrt{d_k}} + \mathbf{M} \right) \mathbf{V} . \qquad(17.4)\] Como \(e^{-\infty} = 0\), cada posição bloqueada recebe um peso exatamente igual a zero, e os pesos restantes de cada linha continuam somando 1. As posições permitidas formam um triângulo inferior: o token \(t\) vê a si mesmo e tudo o que vem antes, nunca nada depois (Vaswani et al. 2017; Radford et al. 2018).

Outras máscaras usam o mesmo truque. Uma máscara de preenchimento (padding mask) bloqueia os tokens de enchimento acrescentados para que notas de comprimentos diferentes caibam em uma mesma tabela, de modo que nenhuma palavra real preste atenção a eles. Um modelo que lê uma nota inteira não usa máscara causal: ele é bidirecional, e “pain” pode prestar atenção a “denies”, antes dele, e a “today” (hoje), depois dele.

17.5 Muitas cabeças, muitas relações

Uma operação de atenção produz um conjunto de pesos por token, uma noção de relevância. Mas uma frase clínica carrega várias relações ao mesmo tempo. Para “creatinina”, na nota de Seán, um vínculo relevante é com o medicamento (por que ela está sendo dosada?), outro com o paciente (de quem é a creatinina?), outro com o tempo (desde quando?). Pedir a um único conjunto de pesos que capte todas elas o transforma em um gargalo.

Definição 17.4 (Atenção com múltiplas cabeças) A atenção com múltiplas cabeças (multi-head attention) executa \(h\) operações de atenção, chamadas cabeças, lado a lado, cada uma com as próprias matrizes de projeção \(\mathbf{W}_Q^{(m)}, \mathbf{W}_K^{(m)}, \mathbf{W}_V^{(m)}\), para que cada cabeça possa aprender a própria noção de relevância: \[ \text{head}_m = \operatorname{Attention}\big(\mathbf{X}\mathbf{W}_Q^{(m)},\, \mathbf{X}\mathbf{W}_K^{(m)},\, \mathbf{X}\mathbf{W}_V^{(m)}\big), \qquad m = 1, \dots, h . \] As saídas das cabeças são colocadas lado a lado (concatenadas) e misturadas por mais uma matriz aprendida \(\mathbf{W}_O\): \[ \operatorname{MHA}(\mathbf{X}) = \big[\text{head}_1, \dots, \text{head}_h\big]\, \mathbf{W}_O . \qquad(17.5)\] Normalmente cada cabeça trabalha com vetores de comprimento \(d_k = d/h\), de modo que as cabeças juntas custam mais ou menos o mesmo que uma única cabeça grande.

Em modelos treinados, as cabeças de fato se especializam. Estudando o BERT, Clark et al. (2019) encontraram cabeças que prestam atenção à palavra anterior ou à seguinte, cabeças que ligam um verbo ao seu objeto direto, um determinante ao seu substantivo ou um pronome ao substantivo a que se refere, nada disso programado por ninguém. A especialização não é garantida, porém, e muitas cabeças têm padrões que resistem a uma descrição simples. O transformer original usava \(h = 8\) cabeças com \(d = 512\) (Vaswani et al. 2017); o BERT-base usa 12 cabeças com \(d = 768\) (Devlin et al. 2019).

Um transformer tem dimensão do modelo \(d = 512\). Seus projetistas passam de 8 cabeças de tamanho \(d_k = 64\) para 16 cabeças de tamanho \(d_k = 32\). O que acontece com o número de pesos de \(\mathbf{W}_Q\), \(\mathbf{W}_K\), \(\mathbf{W}_V\) e \(\mathbf{W}_O\) juntas?

No entanto, a ordem carrega significado: “a creatinina subiu depois que a vancomicina foi iniciada” e “a vancomicina foi iniciada depois que a creatinina subiu” contêm as mesmas palavras e contam histórias clínicas opostas.

Definição 17.5 (Codificação posicional) Uma codificação posicional é um vetor \(\mathbf{p}_t\), um para cada posição \(t\), somado ao embedding do token antes da primeira camada, para que cada vetor de entrada carregue tanto o que é o token quanto onde ele está: \[ \mathbf{x}_t^{(0)} = \mathbf{e}_{w_t} + \mathbf{p}_t . \] As codificações podem ser funções fixas da posição ou ser aprendidas como qualquer outro peso.

O transformer original usava ondas fixas de frequências diferentes: a coordenada \(2r\) de \(\mathbf{p}_t\) é \(\sin(t / 10000^{2r/d})\) e a coordenada \(2r+1\) é \(\cos(t / 10000^{2r/d})\), de modo que cada posição recebe um padrão único e posições vizinhas recebem padrões parecidos (Vaswani et al. 2017). O BERT e os modelos GPT, em vez disso, aprendem um vetor por posição (Devlin et al. 2019; Radford et al. 2019), que é também o que faz o pequeno modelo da Seção 17.10. Muitos modelos recentes codificam a posição relativa girando consultas e chaves por um ângulo que depende da posição, de modo que o escore entre dois tokens depende da distância entre eles (Su et al. 2024).

Um transformer sem nenhuma informação posicional lê “a creatinina subiu depois que a vancomicina foi iniciada” e “a vancomicina foi iniciada depois que a creatinina subiu”. O que ele consegue dizer sobre as duas frases?

17.7 O bloco transformer

A atenção move informação entre os tokens. Sozinha, ainda não é um modelo. O transformer a envolve em um bloco com mais três ingredientes (uma rede feed-forward, conexões residuais e normalização de camada) e empilha muitos blocos idênticos.

A rede feed-forward. Depois que a atenção misturou informação entre as posições, o vetor de cada token passa, sozinho, por uma pequena rede neural do tipo visto no Capítulo 7: uma camada oculta, geralmente quatro vezes mais larga que \(d\), com uma função de ativação não linear \(g\), e de volta à largura \(d\): \[ \operatorname{FFN}(\mathbf{x}) = g(\mathbf{x}\mathbf{W}_1 + \mathbf{b}_1)\,\mathbf{W}_2 + \mathbf{b}_2 . \] Os mesmos pesos são aplicados em cada posição. Um lema útil: a atenção decide para onde olhar; a rede feed-forward decide o que fazer com o que foi encontrado. Sem ela, uma pilha de camadas de atenção só conseguiria formar médias ponderadas de vetores de valor. A ativação \(g\) costuma ser a ReLU ou sua prima suave, a GELU (Nair e Hinton 2010; Hendrycks e Gimpel 2016).

Definição 17.6 (Conexão residual e normalização de camada) Uma conexão residual soma a entrada de uma subcamada à sua saída, \(\mathbf{x} + F(\mathbf{x})\), de modo que a subcamada só precisa aprender uma correção da representação atual; ela também dá aos gradientes um caminho direto através de pilhas profundas (He et al. 2016). A normalização de camada (layer normalisation) reescala cada vetor de token para média 0 e desvio-padrão 1 ao longo de suas \(d\) coordenadas e depois aplica um ganho \(\mathbf{g}\) e um deslocamento \(\mathbf{b}\) aprendidos, coordenada por coordenada: \(\operatorname{LN}(\mathbf{x}) = \mathbf{g} \odot (\mathbf{x} - \mu)/\sigma + \mathbf{b}\), em que \(\mu\) e \(\sigma\) são a média e o desvio-padrão das entradas de \(\mathbf{x}\) e \(\odot\) é a multiplicação entrada por entrada (Ba, Kiros, e Hinton 2016). Ela mantém os números em uma faixa estável à medida que passam por muitas camadas.

O lugar exato da normalização importa, e há duas disposições em uso. O transformer original normalizava depois de somar o resíduo (post-LN): \(\mathbf{X}' = \operatorname{LN}(\mathbf{X} + \operatorname{MHA}(\mathbf{X}))\) (Vaswani et al. 2017). O GPT-2 levou a normalização para a entrada de cada subcamada e acrescentou uma normalização final depois do último bloco (Radford et al. 2019), e Xiong et al. (2020) mostraram por que essa disposição pre-LN é mais fácil de treinar: o caminho residual continua sendo uma via expressa intocada da entrada à saída, os gradientes se comportam bem desde o início e o treino precisa menos do cuidadoso “aquecimento” (warm-up) da taxa de aprendizado que o post-LN exige. A maioria dos modelos atuais usa pre-LN, e este capítulo também.

Definição 17.7 (Bloco transformer (pre-LN)) Um bloco transformer recebe uma matriz \(T \times d\) de vetores de token \(\mathbf{X}\) e devolve uma matriz \(\mathbf{Y}\) de mesmo formato: \[ \mathbf{X}' = \mathbf{X} + \operatorname{MHA}\big(\operatorname{LN}(\mathbf{X})\big), \qquad \mathbf{Y} = \mathbf{X}' + \operatorname{FFN}\big(\operatorname{LN}(\mathbf{X}')\big) . \qquad(17.6)\] Um transformer empilha \(N\) desses blocos, \(\mathbf{H}^{(l)} = \operatorname{Block}_l(\mathbf{H}^{(l-1)})\) para \(l = 1, \dots, N\), a partir de \(\mathbf{H}^{(0)}\), os embeddings dos tokens mais as codificações posicionais. Em um modelo que gera texto, a atenção em cada bloco tem máscara causal.

Observe o invariante: cada subcamada devolve uma matriz \(T \times d\), então as somas residuais estão sempre definidas e os blocos podem ser empilhados tão fundo quanto quisermos. A profundidade serve para um refinamento repetido. Estudos de modelos treinados sugerem que as camadas inferiores tendem a captar padrões locais e superficiais, e as superiores relações mais abstratas, embora o quadro esteja longe de ser nítido (Clark et al. 2019).

Qual parte do transformer faz cada trabalho?

  1. Permite que o vetor de “creatinina” traga informação de “vancomicina”, vinte tokens antes. Atenção
  2. Transforma o vetor de cada token sozinho, por meio de uma camada oculta quatro vezes mais larga. Rede feed-forward
  3. Soma a entrada de uma subcamada de volta à sua saída, para que cada camada aprenda apenas uma correção. Conexão residual
  4. Reescala cada vetor de token para média 0 e desvio-padrão 1 antes de uma subcamada. Normalização de camada
  5. Permite que o modelo saiba que “vancomicina” veio antes de “creatinina”. Codificação posicional
  6. Impede um token de olhar para os tokens que vêm depois dele. Máscara causal

Qual é o tamanho de um bloco? Conte os pesos. Cada uma das matrizes \(\mathbf{W}_Q\), \(\mathbf{W}_K\), \(\mathbf{W}_V\) e \(\mathbf{W}_O\) é \(d \times d\), com um viés de comprimento \(d\); a rede feed-forward tem uma matriz \(d \times d_{\text{ff}}\) com \(d_{\text{ff}}\) vieses e uma matriz \(d_{\text{ff}} \times d\) com \(d\) vieses; cada uma das duas normalizações de camada tem um ganho e um deslocamento de comprimento \(d\). Como mostra o Exercício 17.1, são as redes feed-forward, não a atenção, que guardam a maior parte dos pesos de um transformer.

17.8 Dos vetores à próxima palavra

Depois do último bloco, cada posição \(t\) contém um vetor \(\mathbf{h}_t\) de comprimento \(d\) que reuniu, por meio da atenção, tudo o que precisa dos tokens \(1, \dots, t\). Um modelo de linguagem precisa transformá-lo em uma probabilidade para cada token do vocabulário. Uma camada linear dá um escore (logit) por token, e a softmax do Capítulo 16 transforma escores em probabilidades: \[ \mathbf{z}_t = \mathbf{h}_t \mathbf{E}^{\top}, \qquad P(w_{t+1} = v \mid w_{\le t}) = \frac{e^{z_{t,v}}}{\sum_{u \in \mathcal{V}} e^{z_{t,u}}} . \qquad(17.7)\] Aqui a camada de saída reutiliza a matriz de embeddings \(\mathbf{E}\), uma escolha comum chamada compartilhamento de pesos (weight tying) (Press e Wolf 2017): o logit do token \(v\) é o produto escalar \(\mathbf{h}_t \cdot \mathbf{e}_v\), então o modelo prevê os tokens cujos embeddings melhor correspondem ao estado atual, e economiza uma matriz de \(d \times \lvert\mathcal{V}\rvert\) pesos. Por causa da máscara causal, \(\mathbf{h}_t\) depende apenas dos tokens até \(t\), então a Equação 17.7 é uma previsão genuína do próximo token.

O treino usa a mesma perda do Capítulo 16. Cada posição de cada texto de treino fornece uma previsão, e o modelo minimiza a entropia cruzada média, \[ \mathcal{L}_{\text{AR}} = -\frac{1}{T} \sum_{t=1}^{T} \log P(w_t \mid w_{<t}) , \qquad(17.8)\] ou seja, maximiza a verossimilhança do texto. Não são necessários rótulos (o próximo token é o rótulo), e por isso esse aprendizado é chamado de autossupervisionado. Graças à máscara, todas as \(T\) previsões de um texto são calculadas em uma única passagem paralela, o que explica em grande parte por que os transformers treinam muito mais rápido que as redes recorrentes (Vaswani et al. 2017).

Treino e geração usam a probabilidade condicional de maneiras diferentes. Durante o treino, o modelo sempre recebe os tokens anteriores verdadeiros (isso se chama teacher forcing (Williams e Zipser 1989)). Durante a geração, ele se alimenta das próprias saídas anteriores: prevê uma distribuição, escolhe um token (o mais provável, ou uma amostra, como no Capítulo 16), acrescenta-o e repete. Um modelo pode, portanto, ir bem na perda de treino e ainda assim se desviar em gerações longas e livres, porque uma única escolha improvável muda tudo o que vem depois (S. Bengio et al. 2015).

Juntando as peças, o caminho completo do texto à previsão é: texto → tokens → identificadores de token → embeddings mais posições → \(N\) blocos transformer → normalização de camada final → logits → softmax → probabilidade do próximo token.

17.9 Encoders, decoders e as duas famílias

O transformer original foi construído para tradução, com duas pilhas (Figura 17.4) (Vaswani et al. 2017). Um encoder (codificador) lê todo o texto de origem com autoatenção bidirecional e produz um vetor contextual por token. Um decoder (decodificador) gera a saída um token de cada vez com autoatenção com máscara causal e, em cada bloco, uma terceira subcamada, a atenção cruzada (cross-attention), toma suas consultas do decoder e suas chaves e valores da saída do encoder, para que cada palavra gerada possa olhar de volta para a origem. Um exemplo clínico do mesmo desenho: um encoder lê o resumo de alta de Aoife, e um decoder escreve as instruções em linguagem simples para a filha dela, palavra por palavra, consultando o resumo a cada passo.

Definição 17.8 (Encoder, decoder) Um encoder transformer é uma pilha de blocos com autoatenção bidirecional: cada token pode prestar atenção a todos os outros, e a saída é um vetor contextual para cada token. Um decoder transformer é uma pilha de blocos com autoatenção com máscara causal, usada para gerar texto da esquerda para a direita. Um modelo encoder–decoder liga os dois por meio da atenção cruzada, em que as consultas vêm do decoder e as chaves e os valores, do encoder.

Em dois anos, cada metade tinha se tornado a base de uma família própria, e a diferença entre elas é precisamente a máscara e o objetivo de treino (Figura 17.5).

GPT: só decoder. O Generative Pre-trained Transformer (transformer gerador pré-treinado) mantém apenas a pilha do decoder, sem atenção cruzada, e é treinado com a Equação 17.8 sobre grandes coleções de texto (Radford et al. 2018, 2019). Como sua máscara corresponde à regra da cadeia, ele define uma probabilidade para qualquer texto e pode gerar. Dado o prompt “O paciente foi internado na”, ele calcula uma distribuição para o próximo token, escolhe um (“UTI”), acrescenta-o e repete: “O paciente foi internado na UTI Ala 7 com sepse.” Cada novo token vira contexto para o seguinte, então a geração é cumulativa, e cada escolha molda tudo o que vem depois.

BERT: só encoder. O Bidirectional Encoder Representations from Transformers (representações bidirecionais de encoder a partir de transformers) mantém apenas o encoder e é treinado para preencher lacunas (Devlin et al. 2019). Cerca de 15 % dos tokens de cada texto de treino são selecionados; a maioria deles é substituída por um token especial [MASK] (alguns por um token aleatório, outros ficam inalterados), e o modelo precisa recuperar os originais usando as palavras dos dois lados. A máscara aqui corrompe a entrada, não a atenção: a atenção continua totalmente bidirecional.

Definição 17.9 (Modelagem de linguagem mascarada versus autorregressiva) Um modelo de linguagem autorregressivo prevê cada token a partir dos anteriores e é treinado minimizando a Equação 17.8; ele define uma probabilidade para textos inteiros e pode gerar. Um modelo de linguagem mascarado esconde um conjunto aleatório \(\mathcal{M}\) de posições e é treinado para recuperá-las a partir do restante do texto, \[ \mathcal{L}_{\text{MLM}} = -\sum_{t \in \mathcal{M}} \log P\big(w_t \mid \tilde{w}\big) , \qquad(17.9)\] em que \(\tilde{w}\) é o texto corrompido. Ele aprende representações ricas, dos dois lados, mas não define uma fatoração da esquerda para a direita da probabilidade de um texto, então não é usado para gerar.

A força do BERT é a representação. Um modelo BERT pré-treinado em texto geral pode ser ajustado (fine-tuned) com um pequeno conjunto rotulado para classificar notas (“esta nota descreve uma reação adversa a medicamento?”) ou para encontrar a resposta a uma pergunta dentro de um trecho: dado “O paciente foi internado na unidade de terapia intensiva ontem” e a pergunta “Onde o paciente foi internado?”, ele marca o trecho “a unidade de terapia intensiva” (Rajpurkar et al. 2016; Devlin et al. 2019). O texto clínico e biomédico é suficientemente diferente de jornais e páginas da web para que encoders específicos do domínio ajudem: o BioBERT continuou o pré-treino do BERT em resumos e artigos completos do PubMed (Lee et al. 2020), o ClinicalBERT em notas de terapia intensiva (Alsentzer et al. 2019), e o PubMedBERT foi pré-treinado do zero em texto biomédico, com um vocabulário próprio (Gu et al. 2021). Na UTI Ala 7, uma ferramenta que sinaliza o risco renal relacionado a medicamentos nas notas é uma tarefa de classificação, um trabalho natural para um encoder desse tipo; uma ferramenta que redige o resumo da passagem de plantão é uma tarefa de geração, um trabalho para um decoder. Os grandes modelos de linguagem do Capítulo 18 são decoders: o desenho do GPT, ampliado enormemente.

A equipe de farmácia quer duas ferramentas: (A) uma que rotule cada nota noturna como “possível nefrotoxicidade: sim/não” e (B) uma que redija um resumo matinal da noite para cada paciente. Qual combinação se encaixa melhor nas duas famílias?

17.10 Um pequeno transformer, treinado

Tudo até aqui usou números aleatórios ou escolhidos à mão. Para ver o que faz um transformer treinado, treinamos um pequeno com notas de medicação da UTI Ala 7, escritas em inglês. As notas foram geradas a partir de modelos de frase (o script é scripts/precompute/ch17_tiny_transformer.py), por exemplo:

  aoife was started on vancomycin on friday . tonight we check her creatinine
  priya was started on vancomycin on sunday . the team reviewed her and she sat in the chair and she ate some lunch and she walked to the window and her lines were changed . tonight we check her creatinine

Em cada nota, a última palavra (o exame de sangue a ser verificado esta noite) é determinada pelo medicamento citado no início (vancomicina ou gentamicina → creatinina, creatinine; varfarina → INR; insulina → glicose, glucose; e assim por diante), e os pronomes são determinados pelo nome do paciente. Um número aleatório de frases do dia a dia fica no meio, de modo que o medicamento está entre 8 e 36 tokens antes da última palavra (mediana 19). É o brinquedo “patient … pain” da Seção 17.1, tornado clínico e mais difícil.

O modelo é um transformer pre-LN só com decoder, exatamente como na Figura 17.3, com \(N = 2\) blocos, \(h = 2\) cabeças, \(d = 32\), \(d_{\text{ff}} = 128\), codificações posicionais aprendidas e compartilhamento de pesos: 28 960 pesos no total, dos quais 12 704 por bloco (o número que você calculou na missão). Ele foi treinado por 1500 passos de descida do gradiente em 6 000 notas, em um a poucos minutos na CPU de um notebook com PyTorch (Paszke et al. 2019), e testado em 1 000 notas novas.

O resultado é contundente. Nas notas de teste, o transformer prevê corretamente a última palavra 100 % das vezes. Um preditor de n-gramas que vê apenas as últimas \(k\) palavras não consegue fazer melhor do que apostar no exame mais comum (26 %) até que sua janela seja longa o bastante para alcançar o medicamento, e janelas longas raramente aparecem no treino, de modo que, mesmo com \(k = 16\), ele chega a apenas 41 % (Figura 17.6).

Como ele faz isso? Os pesos de atenção podem ser lidos diretamente do modelo treinado. O widget os mostra para cinco notas de teste, para cada um dos dois blocos (camadas) e cada uma das duas cabeças. Os tokens aparecem em inglês, como o modelo os viu.

Algumas se concentram numa única palavra próxima, outras espalham a atenção de forma mais ampla, e as cabeças da camada 2 quase não colocam peso nenhum no medicamento, e mesmo assim a previsão está certa. Essa última observação é um alerta. É tentador ler mapas de calor de atenção como explicações: “o modelo sinalizou a nota porque prestou atenção à vancomicina”. Mas os pesos de atenção mostram onde a informação foi reunida em uma camada, não do que a previsão depende depois que o fluxo residual, as redes feed-forward e as outras camadas fizeram o seu trabalho. Os estudos divergem sobre o quanto os pesos de atenção revelam: Jain e Wallace (2019) constataram que padrões de atenção muito diferentes podem dar as mesmas previsões, e Wiegreffe e Pinter (2019) mostraram que, testada com mais cuidado, a atenção ainda pode carregar informação útil, mas limitada. Trate os mapas de calor como pistas, não como provas; o Capítulo 12 descreve métodos concebidos para explicação.

A ferramenta de leitura de notas de um fornecedor sinaliza a nota de Aoife e destaca “vancomicina” em vermelho-escuro, dizendo: “a atenção do modelo mostra que a vancomicina gerou o alerta”. Como o comitê de IA deve interpretar isso?

17.11 O preço da atenção e seus limites

O poder da atenção tem um custo. Cada consulta é comparada com cada chave, então um texto de \(T\) tokens precisa de uma tabela \(T \times T\) de escores em cada cabeça de cada camada: cálculo e memória crescem com \(T^2\). Uma nota dez vezes mais longa custa cem vezes mais atenção. É por isso que os modelos têm um comprimento máximo de contexto, e por isso muita pesquisa se dedicou a variantes mais baratas, que prestam atenção a janelas locais, a algumas posições selecionadas ou a resumos comprimidos (Tay et al. 2022).

A arquitetura também tem limites que nenhuma engenharia remove. Um modelo de linguagem transformer é treinado para produzir continuações prováveis, não verificadas. Um texto fluente e errado (uma dose inventada, uma diretriz que não existe) decorre diretamente do objetivo da Equação 17.8 e é chamado de alucinação (Ji et al. 2023). O modelo reproduz os padrões do seu texto de treino, incluindo as lacunas e os vieses. E um texto que parece raciocínio não tem garantia de ser um raciocínio sólido. O Capítulo 18 volta a cada um desses pontos quando os modelos de linguagem se tornam assistentes clínicos.

17.12 Onde isto se encaixa no ciclo de decisão

A atenção permite que a etapa do modelo alcance informação que está em qualquer ponto de um texto, que é o que as notas clínicas exigem: o motivo pelo qual uma palavra importa muitas vezes está muitas palavras longe (Seção 17.1, Seção 17.2). O transformer transforma esse mecanismo em uma arquitetura profunda e treinável (Seção 17.7), e a escolha da máscara decide se ele lê texto para produzir informação, como um alerta, um rótulo ou uma dose extraída (encoders no estilo BERT), ou se produz o próprio texto (decoders no estilo GPT, Seção 17.9). O que pode dar errado? Uma janela de contexto curta demais para a nota (Seção 17.11); um mapa de calor confundido com uma explicação (Seção 17.10); uma saída fluente que não é verdadeira; e, como em todo capítulo, um modelo nunca validado em notas locais. Quem continua no controle? Seán, que lê o alerta à luz da prescrição e do paciente, e decide.

17.15 Resumo

  • Todo modelo de linguagem estima \(P(w_t \mid w_{<t})\); os modelos diferem na forma de representar o contexto. Janelas fixas (n-gramas) não alcançam longe; redes recorrentes comprimem o passado em um único vetor.
  • A atenção constrói o novo vetor de cada token como uma média ponderada de vetores de valor, com pesos positivos, que somam 1 e são calculados a partir do conteúdo.
  • Cada token fornece uma consulta, uma chave e um valor por meio de matrizes aprendidas; \(\operatorname{softmax}(\mathbf{Q}\mathbf{K}^{\top}/\sqrt{d_k})\mathbf{V}\). O \(\sqrt{d_k}\) impede a softmax de saturar.
  • Uma máscara causal (\(-\infty\) acima da diagonal) impede os tokens de ver o futuro, em acordo com a regra da cadeia; os modelos bidirecionais não usam máscara causal.
  • A atenção com múltiplas cabeças aprende vários padrões de relevância em paralelo sem custo extra em pesos; as codificações posicionais dizem à atenção, cega à ordem, onde cada token está.
  • Um bloco transformer pre-LN soma a atenção e uma rede feed-forward a um fluxo residual, cada uma depois de uma normalização de camada; os blocos mantêm o formato \(T \times d\) e são empilhados.
  • A camada de saída transforma cada vetor final em logits e em uma softmax; o treino minimiza a entropia cruzada do próximo token.
  • O GPT (decoder, causal, autorregressivo) gera texto; o BERT (encoder, bidirecional, modelo de linguagem mascarado) o representa; os encoders biomédicos adaptam o BERT ao texto clínico.
  • O custo da atenção cresce com \(T^2\); mapas de atenção são pistas, não explicações; texto provável não é texto verificado.
