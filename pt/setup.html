Apêndice A: Configurando R, Python, Git e GitHub

Tudo neste livro roda no seu navegador, então você pode começar sem instalar nada. Mais cedo ou mais tarde, porém, você vai querer rodar os Labs no seu próprio computador, trabalhar com os seus próprios dados e manter os seus projetos seguros e fáceis de compartilhar. Este apêndice configura as quatro ferramentas que tornam isso possível: R, Python, Git e GitHub. Siga as partes de que você precisa; cada uma termina com uma verificação de que tudo funcionou.

Por que se dar ao trabalho? O Capítulo 1 defendeu que resultados só contam quando outra pessoa consegue reproduzi-los (Seção 1.11). O código é a forma de dizer ao computador exatamente o que fazer, e o controle de versão é a forma de registrar cada alteração nesse código, recuperar-se de erros e trabalhar com outras pessoas sem que uma sobrescreva o trabalho da outra. Na pesquisa e na regulação em saúde, essa rastreabilidade não é um luxo: ela faz parte da evidência.

A.1 Um primeiro contato com código

Código é uma lista de instruções escritas em uma linguagem que o computador entende. O exemplo abaixo cria cinco medidas de frequência cardíaca, calcula a média, exibe uma mensagem e monta uma pequena tabela. Rode-o em qualquer uma das duas linguagens.

  • R
  • Python

A.2 Instale o R e um editor

  1. R. Baixe e instale a versão mais recente para o seu sistema a partir do CRAN, https://cran.r-project.org (R Core Team 2024).

  2. Um editor. Instale o RStudio Desktop (https://posit.co/download/rstudio-desktop/) ou o Positron (https://positron.posit.co), ambos gratuitos. O RStudio também inclui o Quarto, a ferramenta usada para construir este livro.

  3. Os pacotes usados nos Labs. Abra o RStudio e rode, uma única vez:

    install.packages(c("tidyverse", "glmnet", "rpart", "ranger", "mice", "knitr", "rmarkdown"))

Os pacotes são o tidyverse (Wickham et al. 2019), glmnet (Friedman, Hastie, e Tibshirani 2010), rpart (Therneau e Atkinson 2023), ranger (Wright e Ziegler 2017), mice (Buuren e Groothuis-Oudshoorn 2011), knitr (Xie 2015) e rmarkdown (Xie, Allaire, e Grolemund 2018).

Verificação: no console do RStudio, R.version.string exibe a sua versão do R, e library(glmnet) roda sem erro.

A.3 Instale o Python

Há dois caminhos comuns; escolha um.

  • Anaconda ou Miniconda (https://www.anaconda.com/download) instala o Python junto com o gerenciador de pacotes conda. Muitas universidades e hospitais já o utilizam.
  • python.org (https://www.python.org/downloads/) instala o Python puro, que você depois amplia com o pip.

Crie um ambiente separado para o livro, para que os pacotes dele não entrem em conflito com outros:

# com conda
conda create -n aihs python=3.12 pandas numpy scikit-learn matplotlib jupyter
conda activate aihs

# ou com Python puro
python3 -m venv aihs
source aihs/bin/activate          # no Windows: aihs\Scripts\activate
pip install pandas numpy scikit-learn matplotlib jupyter

Você pode escrever Python no VS Code (https://code.visualstudio.com), no Positron, no JupyterLab ou no próprio RStudio.

O Python é mantido pela Python Software Foundation (Python Software Foundation 2025); os pacotes são pandas (McKinney 2010), NumPy (Harris et al. 2020), scikit-learn (Pedregosa et al. 2011) e Matplotlib (Hunter 2007).

Verificação: python -c "import pandas, sklearn; print('ok')" exibe ok.

A.4 Git e GitHub: o que são

O Git é um sistema de controle de versão (Chacon e Straub 2014): ele registra instantâneos dos arquivos de um projeto ao longo do tempo. Cada instantâneo é um commit, com uma mensagem curta dizendo o que mudou e por quê. Com o Git, você pode comparar versões, voltar a uma versão anterior e trabalhar em uma ideia em um branch (ramo) separado, sem mexer na versão principal.

O Git funciona no seu próprio computador. O GitHub (e serviços semelhantes, como GitLab ou Bitbucket) mantém uma cópia do projeto on-line, um repositório remoto, que oferece um backup, um lugar público ou privado para compartilhar o seu trabalho e ferramentas de colaboração: outras pessoas podem propor alterações por meio de um pull request, que você revisa antes de aceitar.

Dados de saúde nunca vão para o GitHub

Repositórios guardam código, documentação e, no máximo, dados simulados ou totalmente anonimizados. Nunca faça commit de dados que identifiquem pacientes, nem mesmo em um repositório privado: liste as pastas de dados em um arquivo .gitignore para que o Git as ignore e siga as regras de proteção de dados da sua instituição (na Europa, o GDPR (European Parliament and Council of the European Union 2016)). Todos os conjuntos de dados deste livro são simulados justamente para que possam ser compartilhados.

A.5 Configure o Git e o GitHub, passo a passo

A.5.1 1. Crie uma conta no GitHub

Acesse https://github.com, cadastre-se com um nome de usuário curto e profissional (ele passa a fazer parte dos endereços dos seus projetos) e ative a autenticação em dois fatores em Settings → Password and authentication.

A.5.2 2. Instale o Git

Verifique se o Git já está instalado digitando em um terminal (a aba Terminal do RStudio serve):

git --version

Se não estiver:

  • macOS: xcode-select --install (ou, com Homebrew, brew install git).
  • Windows: baixe-o em https://git-scm.com/download/win ou rode winget install --id Git.Git -e --source winget.
  • Linux (Debian/Ubuntu): sudo apt update && sudo apt install -y git.

A.5.3 3. Diga ao Git quem você é (uma única vez)

git config --global user.name  "Seu Nome"
git config --global user.email "you@example.com"   # o e-mail da sua conta no GitHub
git config --global init.defaultBranch main

A.5.4 4. Deixe o seu computador se comunicar com o GitHub

O GitHub não aceita a senha da sua conta vinda do Git; ele usa um token de acesso pessoal (personal access token). A forma mais fácil de criar e guardar um é a partir do R:

install.packages(c("usethis", "gitcreds"))
usethis::create_github_token()   # abre o GitHub no navegador; crie o token e copie-o
gitcreds::gitcreds_set()         # cole o token quando solicitado

Se algum dia o Git pedir uma “password” no terminal, cole o token, e não a sua senha do GitHub. (Usuários avançados podem preferir chaves SSH: ssh-keygen -t ed25519 -C "you@example.com" e, depois, adicionar o conteúdo do arquivo .pub em Settings → SSH and GPG keys no GitHub.)

A.5.5 5. Ative o Git no RStudio

Tools → Global Options → Git/SVN: confira se o RStudio encontrou o Git e marque Enable version control interface. Reinicie o RStudio. Uma aba Git passa a aparecer nos projetos que usam Git.

A.5.6 6. Comece um projeto sob controle de versão

Pelo RStudio: File → New Project → New Directory, marque Create a git repository. Depois, no console, usethis::use_github() (Wickham et al. 2023) cria o repositório correspondente no GitHub e conecta os dois.

Pelo terminal:

cd my-project
git init
git add .
git commit -m "Primeira versão"
git branch -M main
git remote add origin https://github.com/<your-username>/my-project.git
git push -u origin main

Verificação: os seus arquivos aparecem em https://github.com/<your-username>/my-project.

A.6 A rotina diária

git pull                         # 1. traz as alterações feitas em outro lugar
# ... editar, rodar, conferir ...
git add analysis.R               # 2. escolhe o que registrar
git commit -m "Adiciona modelo de base para a UTI Ala 7"   # 3. registra, com uma mensagem significativa
git push                         # 4. compartilha

No RStudio, os mesmos quatro passos são botões na aba Git: Pull, marcar os arquivos, Commit, Push. Faça commits de alterações pequenas e coerentes com frequência e escreva mensagens que o seu eu do futuro vai entender (“Corrige vazamento: remove tamanho do tumor pós-tratamento”, e não “alterações”).

Qual comando faz cada tarefa?

  1. Registrar as alterações escolhidas no histórico do projeto, com uma mensagem. git commit
  2. Trazer do GitHub para a sua cópia as alterações mais recentes de um colega. git pull
  3. Enviar ao GitHub as alterações que você registrou. git push
  4. Escolher quais arquivos modificados entrarão no próximo instantâneo. git add

A.7 Quando algo dá errado

Problema O que fazer
git: command not found (macOS) Rode xcode-select --install ou brew install git.
O RStudio não encontra o Git Defina o caminho do Git em Tools → Global Options → Git/SVN e reinicie o RStudio.
Pedido de senha no git push Cole o seu token de acesso pessoal; se ele tiver expirado, rode gitcreds::gitcreds_set() (Csárdi 2022) novamente.
“Divergent branches” ao fazer pull Escolha uma estratégia uma única vez: git config --global pull.rebase false (merge).
Commit feito com o e-mail errado Corrija a configuração com git config --global user.email ... e depois rode git commit --amend --reset-author.
Um arquivo de dados entrou em um commit por engano Não basta apagá-lo em um novo commit: ele continua no histórico. Peça ajuda à equipe de TI ou ao encarregado de proteção de dados da sua instituição antes de fazer push.

A.8 Um portfólio mínimo

Todo ofício tem a sua bancada. Para quem trabalha com dados, um pequeno conjunto de repositórios bem cuidados no GitHub é o portfólio mais simples: cada um com um README curto que diga a que pergunta o projeto responde, como rodá-lo e de onde vêm os dados; código que vá dos dados brutos aos resultados; uma semente aleatória fixa; e um registro das versões dos pacotes (por exemplo, com renv (Ushey e Wickham 2023) no R ou um arquivo requirements.txt no Python). Os Labs deste livro são um bom ponto de partida: coloque cada um em um repositório, modifique-o e deixe o histórico mostrar o que você aprendeu.
