Appendix A: Setting up R, Python, Git and GitHub

Everything in this book runs in your browser, so you can start without installing anything. Sooner or later, though, you will want to run the Labs on your own computer, work with your own data and keep your projects safe and shareable. This appendix sets up the four tools that make that possible: R, Python, Git and GitHub. Follow the parts you need; each one ends with a check that it worked.

Why bother? Chapter 1 argued that results only count when someone else can reproduce them (Section 1.11). Code is how we tell the computer exactly what to do, and version control is how we keep track of every change to that code, recover from mistakes and work with other people without overwriting each other’s work. In health research and regulation, that traceability is not a luxury: it is part of the evidence.

A.1 A first taste of code

Code is a list of instructions written in a language the computer understands. The example below creates five heart-rate readings, computes their average, prints a message and builds a small table. Run it in either language.

A.2 Install R and an editor

  1. R. Download and install the latest version for your system from CRAN, https://cran.r-project.org (R Core Team 2024).

  2. An editor. Install RStudio Desktop (https://posit.co/download/rstudio-desktop/) or Positron (https://positron.posit.co), both free. RStudio also includes Quarto, the tool used to build this book.

  3. The packages used in the Labs. Open RStudio and run, once:

    install.packages(c("tidyverse", "glmnet", "rpart", "ranger", "mice", "knitr", "rmarkdown"))

The packages are the tidyverse (Wickham et al. 2019), glmnet (Friedman, Hastie, and Tibshirani 2010), rpart (Therneau and Atkinson 2023), ranger (Wright and Ziegler 2017), mice (Buuren and Groothuis-Oudshoorn 2011), knitr (Xie 2015) and rmarkdown (Xie, Allaire, and Grolemund 2018).

Check: in the RStudio console, R.version.string prints your R version, and library(glmnet) runs without an error.

A.3 Install Python

There are two common routes; choose one.

  • Anaconda or Miniconda (https://www.anaconda.com/download) installs Python together with the conda package manager. Many universities and hospitals already use it.
  • python.org (https://www.python.org/downloads/) installs plain Python, which you then extend with pip.

Create a separate environment for the book, so that its packages do not clash with others:

# with conda
conda create -n aihs python=3.12 pandas numpy scikit-learn matplotlib jupyter
conda activate aihs

# or with plain Python
python3 -m venv aihs
source aihs/bin/activate          # on Windows: aihs\Scripts\activate
pip install pandas numpy scikit-learn matplotlib jupyter

You can write Python in VS Code (https://code.visualstudio.com), Positron, JupyterLab, or in RStudio itself.

Python is maintained by the Python Software Foundation (Python Software Foundation 2025); the packages are pandas (McKinney 2010), NumPy (Harris et al. 2020), scikit-learn (Pedregosa et al. 2011) and Matplotlib (Hunter 2007).

Check: python -c "import pandas, sklearn; print('ok')" prints ok.

A.4 Git and GitHub: what they are

Git is a version control system (Chacon and Straub 2014): it records snapshots of a project’s files over time. Each snapshot is a commit, with a short message saying what changed and why. With Git you can compare versions, go back to an earlier one, and work on an idea in a separate branch without disturbing the main version.

Git works on your own computer. GitHub (and similar services such as GitLab or Bitbucket) keeps a copy of the project online, a remote repository, which gives you a backup, a public or private place to share your work, and tools to collaborate: other people can propose changes through a pull request, which you review before accepting.

Health data never go to GitHub

Repositories hold code, documentation and, at most, simulated or fully anonymised data. Never commit patient-identifiable data, even to a private repository: list data folders in a .gitignore file so Git ignores them, and follow your institution’s data-protection rules (in Europe, the GDPR (European Parliament and Council of the European Union 2016)). All datasets in this book are simulated precisely so that they can be shared.

A.5 Set up Git and GitHub, step by step

A.5.1 1. Create a GitHub account

Go to https://github.com, sign up with a short, professional username (it becomes part of your project addresses) and turn on two-factor authentication under Settings → Password and authentication.

A.5.2 2. Install Git

Check whether Git is already installed by typing in a terminal (the Terminal tab in RStudio works):

git --version

If it is not:

  • macOS: xcode-select --install (or, with Homebrew, brew install git).
  • Windows: download it from https://git-scm.com/download/win, or run winget install --id Git.Git -e --source winget.
  • Linux (Debian/Ubuntu): sudo apt update && sudo apt install -y git.

A.5.3 3. Tell Git who you are (once)

git config --global user.name  "Your Name"
git config --global user.email "you@example.com"   # the e-mail of your GitHub account
git config --global init.defaultBranch main

A.5.4 4. Let your computer talk to GitHub

GitHub does not accept your account password from Git; it uses a personal access token. The easiest way to create and store one is from R:

install.packages(c("usethis", "gitcreds"))
usethis::create_github_token()   # opens GitHub in the browser; create the token and copy it
gitcreds::gitcreds_set()         # paste the token when asked

If Git ever asks for a “password” in the terminal, paste the token, not your GitHub password. (Advanced users may prefer SSH keys: ssh-keygen -t ed25519 -C "you@example.com", then add the contents of the .pub file under Settings → SSH and GPG keys on GitHub.)

A.5.5 5. Turn on Git in RStudio

Tools → Global Options → Git/SVN: check that RStudio found Git and tick Enable version control interface. Restart RStudio. A Git tab now appears in projects that use Git.

A.5.6 6. Start a project under version control

From RStudio: File → New Project → New Directory, tick Create a git repository. Then, in the console, usethis::use_github() (Wickham et al. 2023) creates the matching repository on GitHub and connects the two.

From the terminal:

cd my-project
git init
git add .
git commit -m "First version"
git branch -M main
git remote add origin https://github.com/<your-username>/my-project.git
git push -u origin main

Check: your files appear at https://github.com/<your-username>/my-project.

A.6 The daily routine

git pull                         # 1. bring in changes made elsewhere
# ... edit, run, check ...
git add analysis.R               # 2. choose what to record
git commit -m "Add baseline model for Ward 7"   # 3. record it, with a meaningful message
git push                         # 4. share it

In RStudio the same four steps are buttons in the Git tab: Pull, tick the files, Commit, Push. Commit small, coherent changes often, and write messages that your future self will understand (“Fix leakage: drop post-treatment tumour size”, not “changes”).

Which command does each job?

  1. Record the chosen changes in the project’s history, with a message. git commit
  2. Bring a colleague’s latest changes from GitHub into your copy. git pull
  3. Send your recorded changes to GitHub. git push
  4. Choose which modified files will go into the next snapshot. git add

A.7 When things go wrong

Problem What to do
git: command not found (macOS) Run xcode-select --install, or brew install git.
RStudio does not see Git Set the path to Git in Tools → Global Options → Git/SVN, then restart RStudio.
Asked for a password on git push Paste your personal access token; if it expired, run gitcreds::gitcreds_set() (Csárdi 2022) again.
“Divergent branches” when pulling Choose a strategy once: git config --global pull.rebase false (merge).
Committed with the wrong e-mail Fix the setting with git config --global user.email ..., then git commit --amend --reset-author.
A data file was committed by mistake Do not just delete it in a new commit: it stays in the history. Ask your institution’s IT or data-protection officer for help before pushing.

A.8 A minimal portfolio

Every craft has its workbench. For anyone working with data, a small set of well-kept GitHub repositories is the simplest portfolio: each with a short README that says what the project answers, how to run it and where the data come from; code that runs from raw data to results; a fixed random seed; and a record of package versions (for example with renv (Ushey and Wickham 2023) in R or a requirements.txt file in Python). The Labs of this book are a good place to start: put each one in a repository, change it, and let the history show what you learned.
