Appendice A: Configurare R, Python, Git e GitHub

Tutto ciò che trovi in questo libro gira nel browser, quindi puoi iniziare senza installare nulla. Prima o poi, però, vorrai eseguire i Lab sul tuo computer, lavorare con i tuoi dati e tenere i tuoi progetti al sicuro e facili da condividere. Questa appendice configura i quattro strumenti che lo rendono possibile: R, Python, Git e GitHub. Segui le parti che ti servono; ognuna si chiude con una verifica che tutto abbia funzionato.

Perché darsi questa pena? Nel Capitolo 1 abbiamo sostenuto che i risultati contano solo quando qualcun altro riesce a riprodurli (Sezione 1.11). Il codice è il modo in cui diciamo al computer esattamente che cosa fare, e il controllo di versione è il modo in cui teniamo traccia di ogni modifica a quel codice, rimediamo agli errori e lavoriamo con altre persone senza sovrascrivere il lavoro gli uni degli altri. Nella ricerca e nella regolamentazione sanitaria questa tracciabilità non è un lusso: fa parte delle evidenze.

A.1 Un primo assaggio di codice

Il codice è un elenco di istruzioni scritte in un linguaggio che il computer comprende. L’esempio qui sotto crea cinque misurazioni della frequenza cardiaca, ne calcola la media, stampa un messaggio e costruisce una piccola tabella. Eseguilo nell’uno o nell’altro linguaggio.

  • R
  • Python

A.2 Installa R e un editor

  1. R. Scarica e installa l’ultima versione per il tuo sistema da CRAN, https://cran.r-project.org (R Core Team 2024).

  2. Un editor. Installa RStudio Desktop (https://posit.co/download/rstudio-desktop/) oppure Positron (https://positron.posit.co), entrambi gratuiti. RStudio include anche Quarto, lo strumento usato per costruire questo libro.

  3. I pacchetti usati nei Lab. Apri RStudio ed esegui, una sola volta:

    install.packages(c("tidyverse", "glmnet", "rpart", "ranger", "mice", "knitr", "rmarkdown"))

I pacchetti sono il tidyverse (Wickham et al. 2019), glmnet (Friedman, Hastie, e Tibshirani 2010), rpart (Therneau e Atkinson 2023), ranger (Wright e Ziegler 2017), mice (Buuren e Groothuis-Oudshoorn 2011), knitr (Xie 2015) e rmarkdown (Xie, Allaire, e Grolemund 2018).

Verifica: nella console di RStudio, R.version.string stampa la tua versione di R e library(glmnet) viene eseguito senza errori.

A.3 Installa Python

Ci sono due strade comuni; scegline una.

  • Anaconda o Miniconda (https://www.anaconda.com/download) installa Python insieme al gestore di pacchetti conda. Molte università e molti ospedali lo usano già.
  • python.org (https://www.python.org/downloads/) installa Python di base, che poi estendi con pip.

Crea un ambiente separato per il libro, in modo che i suoi pacchetti non entrino in conflitto con altri:

# con conda
conda create -n aihs python=3.12 pandas numpy scikit-learn matplotlib jupyter
conda activate aihs

# oppure con Python di base
python3 -m venv aihs
source aihs/bin/activate          # su Windows: aihs\Scripts\activate
pip install pandas numpy scikit-learn matplotlib jupyter

Puoi scrivere Python in VS Code (https://code.visualstudio.com), Positron, JupyterLab o direttamente in RStudio.

Python è mantenuto dalla Python Software Foundation (Python Software Foundation 2025); i pacchetti sono pandas (McKinney 2010), NumPy (Harris et al. 2020), scikit-learn (Pedregosa et al. 2011) e Matplotlib (Hunter 2007).

Verifica: python -c "import pandas, sklearn; print('ok')" stampa ok.

A.4 Git e GitHub: che cosa sono

Git è un sistema di controllo di versione (Chacon e Straub 2014): registra istantanee dei file di un progetto nel tempo. Ogni istantanea è un commit, accompagnato da un breve messaggio che dice che cosa è cambiato e perché. Con Git puoi confrontare versioni, tornare a una versione precedente e lavorare a un’idea in un branch (ramo) separato senza toccare la versione principale.

Git lavora sul tuo computer. GitHub (e servizi simili come GitLab o Bitbucket) conserva una copia del progetto online, un repository remoto, che ti offre un backup, uno spazio pubblico o privato in cui condividere il tuo lavoro e strumenti per collaborare: altre persone possono proporre modifiche tramite una pull request, che tu esamini prima di accettarla.

I dati sanitari non vanno mai su GitHub

I repository contengono codice, documentazione e, al massimo, dati simulati o completamente anonimizzati. Non fare mai il commit di dati che permettono di identificare i pazienti, nemmeno in un repository privato: elenca le cartelle dei dati in un file .gitignore perché Git le ignori, e segui le regole sulla protezione dei dati della tua istituzione (in Europa, il GDPR (European Parliament and Council of the European Union 2016)). Tutti i dataset di questo libro sono simulati proprio perché possano essere condivisi.

A.5 Configurare Git e GitHub, passo dopo passo

A.5.1 1. Crea un account GitHub

Vai su https://github.com, registrati con un nome utente breve e professionale (diventerà parte degli indirizzi dei tuoi progetti) e attiva l’autenticazione a due fattori in Settings → Password and authentication.

A.5.2 2. Installa Git

Controlla se Git è già installato digitando in un terminale (va bene la scheda Terminal di RStudio):

git --version

Se non lo è:

  • macOS: xcode-select --install (oppure, con Homebrew, brew install git).
  • Windows: scaricalo da https://git-scm.com/download/win, oppure esegui winget install --id Git.Git -e --source winget.
  • Linux (Debian/Ubuntu): sudo apt update && sudo apt install -y git.

A.5.3 3. Di’ a Git chi sei (una sola volta)

git config --global user.name  "Nome Cognome"
git config --global user.email "you@example.com"   # l'e-mail del tuo account GitHub
git config --global init.defaultBranch main

A.5.4 4. Fai dialogare il tuo computer con GitHub

GitHub non accetta da Git la password del tuo account; usa invece un token di accesso personale (personal access token). Il modo più semplice per crearne uno e salvarlo è da R:

install.packages(c("usethis", "gitcreds"))
usethis::create_github_token()   # apre GitHub nel browser; crea il token e copialo
gitcreds::gitcreds_set()         # incolla il token quando richiesto

Se Git ti chiede una “password” nel terminale, incolla il token, non la password di GitHub. (Gli utenti esperti potrebbero preferire le chiavi SSH: ssh-keygen -t ed25519 -C "you@example.com", quindi aggiungere il contenuto del file .pub in Settings → SSH and GPG keys su GitHub.)

A.5.5 5. Attiva Git in RStudio

Tools → Global Options → Git/SVN: controlla che RStudio abbia trovato Git e spunta Enable version control interface. Riavvia RStudio. Nei progetti che usano Git compare ora una scheda Git.

A.5.6 6. Avvia un progetto sotto controllo di versione

Da RStudio: File → New Project → New Directory, spunta Create a git repository. Poi, nella console, usethis::use_github() (Wickham et al. 2023) crea il repository corrispondente su GitHub e collega i due.

Dal terminale:

cd my-project
git init
git add .
git commit -m "Prima versione"
git branch -M main
git remote add origin https://github.com/<your-username>/my-project.git
git push -u origin main

Verifica: i tuoi file compaiono su https://github.com/<your-username>/my-project.

A.6 La routine quotidiana

git pull                         # 1. recupera le modifiche fatte altrove
# ... modifica, esegui, controlla ...
git add analysis.R               # 2. scegli che cosa registrare
git commit -m "Aggiunge il modello di base per il Reparto 7"   # 3. registra, con un messaggio significativo
git push                         # 4. condividi

In RStudio gli stessi quattro passaggi sono pulsanti nella scheda Git: Pull, spunta i file, Commit, Push. Fai commit spesso, con modifiche piccole e coerenti, e scrivi messaggi che il te stesso del futuro capirà (“Corregge il leakage: elimina la dimensione del tumore post-trattamento”, non “modifiche”).

Quale comando svolge ciascun compito?

  1. Registrare le modifiche scelte nella storia del progetto, con un messaggio. git commit
  2. Portare nella tua copia le ultime modifiche di un collega da GitHub. git pull
  3. Inviare a GitHub le modifiche che hai registrato. git push
  4. Scegliere quali file modificati entreranno nella prossima istantanea. git add

A.7 Quando qualcosa va storto

Problema Che cosa fare
git: command not found (macOS) Esegui xcode-select --install oppure brew install git.
RStudio non vede Git Imposta il percorso di Git in Tools → Global Options → Git/SVN, poi riavvia RStudio.
Richiesta di password durante git push Incolla il tuo token di accesso personale; se è scaduto, esegui di nuovo gitcreds::gitcreds_set() (Csárdi 2022).
“Divergent branches” durante il pull Scegli una strategia una volta per tutte: git config --global pull.rebase false (merge).
Commit fatto con l’e-mail sbagliata Correggi l’impostazione con git config --global user.email ..., poi esegui git commit --amend --reset-author.
Un file di dati è finito per errore in un commit Non basta cancellarlo con un nuovo commit: resta nella storia. Prima di fare push, chiedi aiuto al servizio IT o al responsabile della protezione dei dati della tua istituzione.

A.8 Un portfolio minimo

Ogni mestiere ha il suo banco di lavoro. Per chi lavora con i dati, un piccolo insieme di repository GitHub ben curati è il portfolio più semplice: ciascuno con un breve README che spieghi a quale domanda risponde il progetto, come eseguirlo e da dove provengono i dati; codice che porti dai dati grezzi ai risultati; un seme casuale fisso; e una registrazione delle versioni dei pacchetti (per esempio con renv (Ushey e Wickham 2023) in R o con un file requirements.txt in Python). I Lab di questo libro sono un buon punto di partenza: mettine ciascuno in un repository, modificalo e lascia che la storia mostri che cosa hai imparato.
